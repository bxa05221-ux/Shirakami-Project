# Conflict / Deadman / Life Boundary Specification

## Purpose

Preserve human conflict while opening alternative future paths.

The boundary does not attempt to make the human choose correctly. It records:

- competing internal signals such as "act" and "stop"
- a Deadman Test: what happens if the candidate path is followed
- a Life Test: what viable futures remain if that path is not required
- a Loss Path: what can be surrendered while preserving selected values

## Cognitive structure

```
Observation
   ↓
Conflict
 ├─ act
 ├─ stop
 ├─ wait
 └─ alternative
   ↓
Deadman Test
   ↓
possible failure path

Life Test
   ↓
alternative viable path

Loss Path
   ↓
what can be surrendered while preserving life/recovery
   ↓
Human Gate
```

## Principles

1. Conflict is an observation state, not an error state.
2. "Act" and "stop" are both preserved.
3. Deadman results are warnings/candidates, not decisions.
4. Life paths search for viable alternatives rather than merely prohibiting an action.
5. Loss paths allow partial defeat without treating defeat as Game Over.
6. Minority and unresolved signals remain available to later re-observation.
7. Human Gate remains required.
8. Decision authority remains false.

## Non-goals

This boundary does not:
- select a winner by majority;
- force an action;
- declare a human choice correct;
- provide instructions for harmful or illegal activity;
- replace legal, medical, financial, or other domain-specific professional judgment.

## Relation to existing boundaries

```
Observation Set
   ↓
Conflict
   ↓
Deadman / Life / Loss
   ↓
Re-observation
   ↓
Recognition Change
   ↓
Context Transition
   ↓
Human Gate
```

This boundary is an extension point for ThreadRPG and one-person mode. A one-person presentation may compress multiple signals into a single conversational interface without converting that interface into an authority.
