# JOUMON PoC Specification v0.1

## Status

- status: experimental-specification
- code_name: JOUMON
- scope: minimal multi-runtime replacement proof
- publication_authorization: pending
- ip_review: pending
- human_gate: pending

## 1. Purpose

This PoC tests one narrow property of the JOUMON integration model:

> The same Shirakami Context and Protocol can be executed through replaceable runtimes while preserving the Context, Evidence, and Human Gate boundaries.

The PoC is not an AI quality benchmark and does not compare providers.

## 2. Non-Goals

The PoC does not:

- rank AI models or providers;
- transfer authority to a runtime;
- require a specific provider;
- measure intelligence, accuracy, or commercial value;
- expose credentials or private prompts;
- authorize publication of implementation details.

## 3. Minimal Data Contract

### Context

A Context is an immutable input bundle for one execution.

Required fields:

- `context_id`
- `task`
- `constraints`
- `authority`

The `authority` field must explicitly state that final decision authority remains human.

### Protocol

A Protocol describes how a runtime is invoked.

Required fields:

- `protocol_id`
- `input_context_id`
- `runtime_role`
- `human_gate_required`

### Runtime Result

A Runtime Result contains output generated by a replaceable runtime.

Required fields:

- `runtime_id`
- `context_id`
- `output`
- `observed`

### Evidence

Evidence records execution facts without granting authority.

Required fields:

- `evidence_id`
- `context_id`
- `runtime_id`
- `observed_output`
- `authority`

The Evidence authority value must remain `non-authoritative`.

### Human Gate

The Human Gate is the only decision boundary in this PoC.

Required fields:

- `decision_status`
- `decision_authority`

The decision authority must remain `human`.

```

       |
     JOUMON
       |
   +---+---+
   |       |
Runtime A Runtime B
   |       |
Evidence A Evidence B
   +---+---+
       |

       |
 Verification
```

## 5. Runtime Adapter Contract

Every runtime adapter exposes the same conceptual operation:

```text
execute(context, protocol) -> runtime_result
```

The adapter must not modify the Context authority boundary.

A runtime may:

- generate text;
- generate code;
- simulate reasoning;
- return structured output.

A runtime may not:

- approve its own result as final;
- replace the Human Gate;
- alter the declared decision authority.

## 6. PoC Test Task

Use a deliberately simple task so that provider/model quality is not the variable under test.

Example:

```text
Task: Produce one short candidate action for the supplied Context.
Constraint: State that the candidate requires human review.
```

The test should run the same Context and Protocol against at least two replaceable Runtime Adapters.

## 7. Success Conditions

The PoC passes its architectural test when:

1. The Context identifier is identical across Runtime A and Runtime B.
2. The Protocol identifier is identical across Runtime A and Runtime B.
3. Both results are linked to the same Context.
4. Evidence records identify the runtime that produced each result.
5. Evidence remains non-authoritative.
6. Human Gate remains the final decision boundary.
7. Runtime-specific details remain outside the canonical Context/Protocol semantics.
8. Replacing Runtime A with Runtime B does not require changing the authority model.

## 8. Failure Conditions

The PoC fails if any runtime:

- becomes the declared final authority;
- mutates the authority field;
- requires provider-specific semantics in the canonical Context;
- prevents execution through another adapter;
- produces evidence that cannot identify its runtime provenance.

## 9. Implementation Constraint

The first implementation should use deterministic mock adapters before live provider calls.

Live OpenAI/Gemini/Claude/Copilot/etc. integration is a later phase. Credentials must never be embedded in the PoC fixtures.

## 10. Evidence to Record

For each run, record:

- Context ID
- Protocol ID
- Runtime ID
- adapter version
- output
- observation status
- evidence ID
- Human Gate status
- verification status

Do not record secrets.

## 11. Expected Demonstration

A successful demonstration should make this statement observable:

> Same Context. Different Runtime. Same Authority Boundary.
